# This is NOT the Next.js you know

This app uses Next.js 16 (App Router, JavaScript, plain CSS). APIs and conventions differ from older versions: read the guide in `node_modules/next/dist/docs/` before writing code (Middleware is now `proxy.js`; route `params` and `cookies()` are async).

## Project notes

- QRS Tasks: the marketing team's board (README.md). Areas, statuses, repeats and starter tasks: `lib/areas.js`. Storage: `lib/store.js` (Supabase table `team_tasks` from `scripts/supabase-tasks.sql` when `SUPABASE_URL` + `SUPABASE_SECRET_KEY` are set, else `data/tasks.local.json`). Login: `lib/auth.js` (shared `TEAM_PASSWORD`, signed cookie; no password locally when it is unset, locked on Vercel when it is unset). API: `app/api/tasks` (GET, POST one or many), `app/api/tasks/[id]` (PATCH, DELETE; a repeating task marked done creates its next copy), `app/api/login`, `app/api/logout`. UI: `components/TaskApp.jsx` (tabs, counts, toolbar, Board and List), `Calendar.jsx` (month grid, drag to reschedule, "No date yet" tray), `TaskDialog.jsx`, `shared.jsx` (cards, dates).
- Keys only in `.env.local` and Vercel.
- Sign-in (October 26 2026): Supabase magic links (`lib/supabaseAuth.js`: `/auth/v1/otp` with `create_user: false`, the Magic Link template points at `{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=email`, `app/auth/confirm` verifies it and sets the app's own signed cookie). Roles are `app_metadata.tasks_role` (`admin` | `member`), never `role` (the QRS website dashboard uses `role` in the same Supabase project). `TASKS_ADMIN_EMAILS` bootstraps the first admin. Team page `/users` (`components/TeamManager.jsx`, `app/api/users`). Without Supabase: local admin mode on a computer, locked on Vercel.
- Data (`lib/db.js`: Supabase REST or `data/<table>.local.json`): `team_tasks` (with `assignee_id`, `created_by_id`, `disposition`, `disposition_note`), `team_task_comments`, `team_notifications`. `lib/store.js` holds the task and comment rules and sends notifications through `lib/notify.js` (who gets what is documented there). UI: `components/Comments.jsx`, `Notifications.jsx` (the bell, plus overdue/due-today reminders computed from the board), dispositions in `TaskDialog.jsx` and on cards.
- Tested against a stand-in Supabase (sign-in, roles, team actions, comments, dispositions, notifications by role); the stand-in is not in the repo.
- Open board (owner, October 26 2026): no sign-in unless `REQUIRE_LOGIN=true` (`openAccess` in `lib/auth.js`). Everyone is treated as a local admin (`user.local`), the person's name comes from the `qrs_name` cookie set by the "Set your name" button, the bell shows only their own due/overdue tasks by name, and the Team page is hidden. The magic-link sign-in, roles and per-login notifications are unchanged behind the switch.
